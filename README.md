이진트리 구현 및 비교 (배열 vs 연결 자료구조)

이 프로젝트는 트리의 괄호 표기법을 입력받아 1차원 배열 방식과 포인터(연결 자료구조) 방식으로 이진트리를 각각 구현하고, 메모리 사용량 및 탐색 효율성을 비교 분석한 과제 보고서입니다.

---

1. 파일 구성
- arrayTree.c : 1차원 배열을 이용한 이진트리 구현 및 특정 노드 탐색
- pointerTree.c : 노드와 포인터를 이용한 이진트리 구현 및 특정 노드 탐색
- README.md : 분석 결과 및 성능 비교 보고서

---

2. 메모리 사용량 비교 분석

(1) 노드 1개당 메모리 크기 기준 (64-bit C 컴파일러 기준)
- 배열 요소 (char): 1 Byte
- 포인터 노드 (char + left 포인터 + right 포인터): 24 Bytes (메모리 정렬 패딩 포함)

(2) 트리 형태별 메모리 비교 (노드 개수 N, 높이 h)

1) 포화/완전 이진트리 (예: N=7, h=3)
- 배열 방식: 7 Bytes
- 포인터 방식: 7 x 24 = 168 Bytes
- 분석: 빈 노드가 없으므로, 노드당 포인터 오버헤드가 없는 배열 방식이 메모리를 훨씬 적게 사용합니다.

2) 일반 이진트리 (예: N=5, h=3)
- 배열 방식: 최대 인덱스 7 사용 (7 Bytes)
- 포인터 방식: 5 x 24 = 120 Bytes
- 분석: 중간에 비어있는 자리가 있어도 노드 크기 자체가 작아 배열 방식이 절대적 메모리는 적습니다.

3) 편향 이진트리 (예: 오른쪽으로만 치우친 트리, N=4, h=4)
- 배열 방식: 2^4 - 1 = 15 Bytes (높이 h가 커질수록 2^h로 지수적 증가)
- 포인터 방식: 4 x 24 = 96 Bytes (노드 개수에 비례하여 N x 24 Bytes 선형 증가)
- 분석: 편향 트리는 깊이가 높아질수록 배열의 빈 공간 낭비가 매우 심해집니다. 반면 포인터 방식은 실제 존재하는 노드 수만큼만 메모리를 사용하므로 편향 트리일수록 포인터 방식이 유연하고 안정적입니다.

---
3. 특정 노드 탐색 효율성 비교 (부모, 자식, 형제 탐색)

(1) 알고리즘 및 시간 복잡도 비교

1) 자식 노드 탐색
- 배열: O(1) (왼쪽: 2*i, 오른쪽: 2*i + 1 인덱스 연산)
- 포인터: O(1) (left, right 포인터 직접 접근)
- 분석: 두 방식 모두 O(1)로 동일하게 효율적입니다.

2) 부모 노드 탐색
- 배열: O(1) (i / 2 인덱스 연산으로 즉시 접근)
- 포인터: O(N) (부모 포인터가 따로 없으므로 루트부터 전체 트리를 다시 탐색해야 함)
- 분석: 배열 방식이 압도적으로 유리합니다.

3) 형제 노드 탐색
- 배열: O(1) (인덱스의 홀수/짝수 여부에 따라 i+1, i-1 접근)
- 포인터: O(N) (부모 노드를 먼저 찾은 후 반대쪽 자식을 확인해야 함)
- 분석: 배열 방식이 압도적으로 유리합니다.

---

4. 종합 결론

1. 완전 이진트리이거나 부모/형제 노드를 찾는 연산이 자주 일어나는 경우에는 인덱스 수학 계산이 가능한 배열 방식이 메모리와 속도 면에서 모두 유리합니다.
2. 트리의 깊이가 깊어지거나 한쪽으로 치우친 편향 이진트리 형태가 발생하는 경우에는 불필요한 배열 공간 낭비를 막아주는 포인터 방식이 더 유리합니다.
